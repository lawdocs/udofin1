# Phase 05 security review (13 Oct 2026)

A static review of the borrower surface by an independent reviewer (no code was run by the reviewer). No critical or high findings and no cross-borrower access, staff-as-borrower, expired or unconsented submission, or non-system deletion path was found. This page records every finding and what was done. It is not a certification.

| #   | Finding                                                                                                      | Severity | Outcome                                                                                                                                                                                             |
| --- | ------------------------------------------------------------------------------------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Phone number passed as a navigation parameter (visible in the route)                                         | Medium   | Fixed: the code screen reads the number from memory only; test coverage is by review (no UI test)                                                                                                    |
| 2   | Step-up code guessing over time (25 guesses per 15 minutes, no overall budget)                               | Medium   | Fixed in the database: two locked challenges in 24 hours stop new codes (pgTAP). Still 6 digits; an 8-digit code is a product choice. The route limit is per address                                 |
| 3   | Database functions accept a caller-supplied code hash and attestation level; only safe while the API is the sole path | Medium   | Accepted for now: PostgREST exposes only `public`, the API pool is the only caller, and the API generates the hash and level itself. Revisit if any RPC exposure is added; a guard test is a follow-up |
| 4   | A captured signed hook request could be replayed inside the 300 s window                                     | Medium   | Mitigated: message ids are remembered for 10 minutes per process (tested). With several API instances a replay may reach another one; a shared store is a follow-up                                  |
| 5   | SMS timeout configured but not applied                                                                       | Low      | Fixed and tested (slow provider: hook answers 500 within the budget, step-up records `timeout`)                                                                                                      |
| 6   | Custom JSON parser dropped prototype-poisoning protection and could echo body fragments in errors             | Low      | Fixed: Fastify's default parser is reused; failures return a fixed `invalid_json` message (tested)                                                                                                   |
| 7   | A closing account can still record consents, start step-up and integrity checks                              | Low      | Open: harmless for data but untidy; tighten `require_borrower` for writes other than cancelling deletion                                                                                             |
| 8   | Submission accepts a grant of an older notice version                                                        | Low      | Open decision for compliance: should a newer published version force re-consent before sending a request?                                                                                           |
| 9   | Anonymisation is partial: the audit trail keeps the user id, and the phone stays in the auth provider         | Low      | Known and documented (D-25, D-38); not described as erasure                                                                                                                                         |
| 10  | An expired, unswept draft cannot be withdrawn                                                                | Info     | Left: it already reads as expired and can no longer be sent                                                                                                                                         |
| 11  | Generic client call allow-list allowed percent-encoded dot segments                                          | Low      | Fixed and tested                                                                                                                                                                                    |
| 12  | Idempotency keys use a non-secure random source                                                              | Info     | Accepted: keys are not secrets; the server binds each to its request                                                                                                                                 |
| 13  | `APP_ENV` defaults to `local`, so a deployment that forgets to set it would allow mocks                      | Low      | Open: make `APP_ENV` mandatory when `NODE_ENV=production` (follow-up)                                                                                                                               |
