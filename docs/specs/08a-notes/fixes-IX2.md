## 3. Needs from other areas

- `services/api/src/system/payments.ts` (`CONFIG_SELECT`, used by the worker for payment intents and mandates) and `system/jobs.ts` (IX) load the configuration without `secret_namespace`. The worker is protected by `withLenderSecretNamespace`, which derives the lender's namespace from `lenderOrgId` (the same rule as the database) and requires both names to start with it. It cannot check that `secret_namespace` is stored, because the row does not carry it. To make the worker check identical to the receiver's: select `secret_namespace` and `private.secret_ref_prefix(c.lender_org_id)` there and call `secretNamesInNamespace` (exported from `system/secret-namespace.ts`). Not needed for safety, only for symmetry.
- `packages/portal-kit/test/setup.test.tsx` (not my area; the `setup` folder): EIGHT portal-kit tests fail against the new contract because their fixtures use bare secret names (`LENDER_PSP_ONE`, lines about 138, 317, 904, 2293 and the loop at about 971): `PaymentConfigDraftInput` now takes only names inside a lender namespace. The portal's own shape check (`SECRET_NAME` in `src/setup/wording.ts`) already accepts a namespaced name, so only the fixtures and the form need to follow: use a name such as `L0198B3F40001_PSP_ONE`, and have the draft form read `GET /v1/lender/secret-ref-prefix?lenderId=` and show the prefix beside the two fields. Run: `CI=1 pnpm --filter @udofin/portal-kit test` (8 failed, 1049 passed on this branch).
- The lender portal should show the prefix returned by `GET /v1/lender/secret-ref-prefix` next to the two secret-name fields and use the new routes (withdraw a claim or a settlement account request; for the platform: the own-account list page, the hold flag `holdKind` on a configuration and the release action). The ops portal should show `holdKind` on suspended configurations.
- Docs (the lead's): `phase-08a-activation-gates.md` (the activation order of `fixes-SA.md` section 5, now proved over HTTP by `lender-activation.integration`), controls matrix MNY-02 (the attestation belongs under "Not evidenced" until it is made with real evidence), `accounts.md`. Provisioning the secrets under the namespaced names in the secrets manager is a platform operation; existing deployments that named secrets without the prefix stop resolving (none exists: no real provider adapter yet).

## 4. Decisions for the owner

1. A platform path for the secret prefix was NOT added (`GET /v1/lender/secret-ref-prefix` only). The SQL function also allows a platform person with the provider permission, and the lender path serves them too (no route-level lender check), but a `/v1/platform/...` twin would be the natural home if the ops portal needs it. Say if wanted.
2. `holdKind` and `holdSetAt` were added to the configuration entry (lender and platform reads, default `null` for existing parsers). The brief did not list them; without them nobody can see a hold, so the release route would be blind. Remove them if you want the hold invisible to lenders.
3. The attestation stays a decision of ONE platform person (fixes-SA decision 5); the routes follow it: attest needs `platform.accounts.registry.verify`, withdraw either registry permission.
4. The worker wrapper leaves MOCK configurations alone (a mock reads no secret, and its fixture names exist in local development and tests only).

## 5. Risks seen and not fixed

- The routing connector secret (`signing_secret_ref` of a lender connector, read by `workers/lender-callbacks.ts` and `modules/routing`) is also a lender-chosen NAME resolved with `process.env[name]` (`callbacks-main.ts` still passes `process.env` for it). It is not a payment configuration and is outside U51, but it is the same class of defect. Left as it was.
- `secret_namespace` null on a legacy row means the receiver treats the webhook secret as missing (deliveries are recorded unverified, reason class `no_secret`); the lender must draft a new configuration. By design (fail closed).
- Thirteen tests of the full API suite still fail on this branch; none is caused by this stream (section 6 lists them): the committed `docs/api/openapi.json` is stale (the lead regenerates it; the test passes after `pnpm --filter @udofin/api openapi`, checked locally and the file restored), three `lender-reminders` tests expect `unsafe_free_text` where the reminders migration now answers `wording_invalid`, one `lender-servicing`, two `payments` and two `servicing` tests are on the IX list (items 5a, 5d, 5b), and four `provider-callbacks` tests need the IX `seenCount` helper change (item 5c; they fail with `expected '0' to be '1'` on `ops.seen_webhooks`, with or without the namespaced fixture).
- `account-fingerprint.ts` is still best effort (leading zeros, merged bank codes are not folded). Only the comment changed.
