## 3. Needs from other areas

- None for the screens to work. For better screens: the platform read of a payment configuration could carry who set a hold (or whether the caller did), so the release button can be hidden from that person (owner decision 2).
- The lead regenerates `docs/api/openapi.json` (not committed here).

## 4. Decisions for the owner

1. **Reason length of a hold release.** The brief said 10 to 200 plain characters; the contract and the database accept 10 to 1000. The form and the operation use 200 (a subset of what the API accepts). Say if it should be 1000 like the other platform reasons.
2. **Who set a hold.** The contract carries `holdKind` and `holdSetAt` only, so the page states the rule before the person tries and after a `self_approval` refusal but cannot say "you set this one". Adding the setter (or a boolean) to the platform read would allow hiding the button.
3. **Pre-filled prefix.** The name fields start with the lender's prefix (the person types the rest), so a field left alone is refused by the browser. The alternative is an empty field with the prefix in the hint. Say if the earlier "form starts empty" rule should win.
4. **No lender screen for `own_account_list_not_attested`.** No lender route answers it today; it is worded for when one does.

## 5. Risks seen and not fixed

- The lender's list of configurations does not show a hold (only the configuration page does).
- The platform has no screen for the kill switch (`suspend`) or `retire` of a configuration: the API has both, the brief did not list them.
- `looksLikeSecretValue` is a convenience check on names; the API and the database stay the authority on the namespace, and the resolvers never read a name outside it.
- The pages have no unit tests (the portals have no runner); the production builds succeeded, the server-to-client hand-off of the actions was not exercised in a browser.
- The prefix is derived from the lender id and is not a secret, but it is printed on the page and held in a hidden field; it is never put in an address or a log line.
