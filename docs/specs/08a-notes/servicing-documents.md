# Phase 08a notes: stream LENDER-ISSUED DOCUMENTS, QUOTES, CLOSURE (database)

Migration `supabase/migrations/20261018000912_p08a_servicing_documents.sql` (forward-only; no new enum values). pgTAP: `supabase/tests/018_p08a_servicing_documents.test.sql` (294 assertions). Snapshot edits: `006_authorization_matrix` (six tables, all `-` for anon, `s` for authenticated and service_role) and one expected-value line in `012_documents_kfs_acceptance` (the list of seeded draft rules now includes the three servicing rules; this file is outside the stream's ownership list, see "Not done" below). `001_structure` needed no edit (it checks every domain table generically).

Read the code, not only this note. Error convention in the tests: `SQLSTATE|hint`. 42501 not authorised (also MFA: hint `mfa_required`), P0002 not found, 22023 bad input, 55000 rule or state, 23505 duplicate, 23503 reference. A privilege error on a table or function (a missing GRANT) is 42501 with no hint of ours; on the Supabase image it carries "Grant the required privileges ..." so never assert an exact hint on it.

## 0. Principles that shape the design

- Statements, foreclosure quotations, NOCs and closure letters are LENDER-ISSUED. Nothing here generates or renders one (a test searches the function names). The schema stores opaque storage keys and SHA-256 hashes only; the production document store does not exist, so reads of the bytes must stay impossible outside local and test (API and adapter concern).
- Every write function calls `private.require_feature(lender, 'statements_noc')` (55000, hint `feature_disabled`). Borrowers have NO table access at all: they read through definer functions that also hide the feature when the switch is off. Lender staff read their own rows through forced RLS (`loan.read`; note that `loan.read` is platform-grantable, so a platform auditor can read the metadata rows like every other loan row, but cannot open lender-issued content, see 3).
- Fail closed on rules: due dates come from an APPROVED, effective `documents.applicability_rules` row; with none, the due date and the rule id are both empty ("rule unresolved") and the request or task is still recorded.
- The closure record and its outbox event are written whether or not the `statements_noc` switch is on (reminders must stop and mandates must be cancelled regardless); the switch decides what borrowers and lenders can DO with the record.

## 1. Rules seeded (all `draft`, never approved)

Table `documents.applicability_rules`, new rule keys (version 1), plus three rows in `documents.document_types` (`statement_of_account`, `noc`, `security_release`; `data_source = 'lender_issued'`, which this migration adds to the check constraint; issuing authority stays `lender`). Periods are DATA in `validity_rule = {"kind":"calendar_days","days":n,"basis":...}`.

Lender categories `nbfc_icc`, `nbfc_d` only (the same scope as the KFS rule; banks, UCBs, HFCs are not covered). Approving a rule goes through the existing Phase 07 two-person flow (`documents.decide_rule`, `platform.documents.manage`); tests approve by owner update.

`private.servicing_rule_days(p_lender, p_rule_key, p_product_category, p_on) returns table (rule_id, days)` (no grants, definer-only helper): looks up the lender's category in `onboarding.lender_profiles`, takes the highest-version APPROVED, effective rule whose lender and product categories match (`p_product_category` null = no product filter), and returns nothing if its `validity_rule` is not `{"kind":"calendar_days","days":1..9999}` (a malformed newest version does NOT fall back to an older one; tested). Product category comes from `lending.loan_requests.category_key` via the application. The security-release rule is resolved WITHOUT a product filter (the lender-reported collateral decides applicability).

Because `loan_documents` has column-level grants, a client must list columns (`select *` fails with 42501). The 006 matrix reads it as `s` for both roles.

Triggers worth knowing (they apply to every writer, including the table owner): `servicing_guard_loan_document` and `servicing_guard_quote` refuse `source = 'mock'` unless `udofin.allow_mock_providers = on` (42501, hint `mock_provider_blocked`), a future `issued_at` / `as_of` (more than 5 minutes ahead; 22023), a supersession that is not the same kind and loan (22023 `supersedes_invalid`), a quote letter that is not a `foreclosure_quote` document (22023 `letter_invalid`). `servicing_protect_document_request` (P0001, hints `request_immutable`, `request_final`; 55000 `request_kind_mismatch`). `servicing_protect_closure` (P0001 `closure_immutable`). `servicing_protect_release_task`: a task is inserted `open` only (55000 `lender_confirmation_only`); to become `confirmed_by_lender`, `confirmed_by` MUST be a user holding `servicing.document.issue` in THAT lender (42501 `lender_confirmation_only`), so the system role, platform staff and other lenders can never be the confirmer, even for the owner (P0001 `task_immutable` / `task_final` for other edits).

## 3. Functions (SECURITY DEFINER, `set search_path = ''`, `revoke all ... from public, anon`)

"Lender user" = `servicing.document.issue` in that lender and `aal2` (hint `mfa_required`); a user who cannot even read the lender's loans (`loan.read`) gets P0002, a reader without the permission gets 42501 (no existence oracle across lenders). Borrower functions answer P0002 for a loan that is not the caller's.

Borrower (`authenticated`):

- `servicing.request_document(p_loan uuid, p_kind text, p_idempotency_key text, p_period_from date default null, p_period_to date default null) returns uuid`. Order of checks: loan ownership (P0002), feature (55000 `feature_disabled`), kind (22023 `kind_invalid`), key `^[A-Za-z0-9._:-]{8,100}$` (22023 `idempotency_key_invalid`), replay (same key and content returns the id; different content 23505 `idempotency_conflict`), then: statements need both or neither period ends, forward, not in the IST future (22023 `period_invalid`); other kinds refuse a period (22023 `period_not_allowed`); `foreclosure_quote` needs an `active` loan (55000 `loan_not_active`); `noc` / `closure_letter` need `closed` or `foreclosed` (55000 `loan_not_closed`); a cancelled loan has no statement (55000 `loan_status_not_eligible`); a second open request of the kind: 23505 `open_request_exists`. Due date: statement -> `servicing.statement_sla_days_default`, noc and closure_letter -> `servicing.noc_sla_days_default`, foreclosure_quote -> none. Audit `servicing.document_request.created`.
- `servicing.cancel_document_request(p_request uuid) returns text` ('cancelled'; 55000 `request_not_open`).
- `servicing.my_document_requests(p_loan uuid) returns table (request_id, kind, status, period_from, period_to, requested_at, due_by, due_rule_key, due_evidence_status, lender_note, decided_at, fulfilled_document_id, fulfilled_quote_id)`. Empty when the switch is off. `due_rule_key` and `due_evidence_status` let the app say "platform default, not a regulatory deadline" (label `unverified`).
- `servicing.my_loan_documents(p_loan uuid) returns table (document_id, kind, issuer, lender_reference, issued_at, period_from, period_to, size_bytes, sha256, source, superseded_by_id)`. Empty when the switch is off; mock-source rows are hidden unless mocks are allowed. The app should show a non-production watermark/banner for `source = 'mock'`.
- `servicing.open_loan_document(p_doc uuid, p_purpose text default 'download') returns jsonb` -> `{document_id, loan_account_id, kind, storage_key, sha256, size_bytes, mime_type, lender_reference, source}`. Writes the access row first. The API MUST then fetch the bytes and verify the SHA-256 before streaming (`Cache-Control: no-store`). P0002 for another borrower's document, 22023 `purpose_invalid`, 55000 `feature_disabled`.
- `servicing.my_closure(p_loan uuid) returns jsonb` (null while no closure record exists; 55000 `feature_disabled`). Snake_case keys: `loan_account_id, lender_display_name, loan_status` (live), `closure_kind, closure_recorded_at, noc_status` (`pending`|`issued`), `noc_status_source` ('lender'), `noc_prompt_key`, `noc_due_by, noc_due_basis {rule_key, rule_version, evidence_status}, noc_document_id, noc_issued_at, security_release_tasks[]` each `{task_id, collateral_type, status, status_source:'lender', prompt_key, lender_confirmed, due_by, due_basis, delay_reason, confirmed_at}`. Prompt keys (the app maps them to en/hi text): `closure.noc.lender_to_issue`, `closure.noc.issued_by_lender`, `closure.security_release.<collateral_type>.lender_to_release`, `closure.security_release.<collateral_type>.lender_confirmed`. THE KEYS NEVER SAY THAT ANYTHING WAS RELEASED; only the lender's confirmation changes the key and `lender_confirmed`. The app text should read "<lender_display_name> will release ...; status: as reported by the lender".

Lender user (`authenticated`):

- `servicing.decline_document_request(p_request uuid, p_note text) returns text` ('declined'; note 10 to 500 chars after trimming, without personal data: 22023 `note_invalid`; 55000 `request_not_open`).
- `servicing.register_loan_document(p_loan, p_kind, p_storage_key, p_sha256, p_size_bytes, p_mime_type, p_lender_reference, p_issued_at, p_period_from default null, p_period_to default null, p_supersedes default null, p_request default null, p_source default 'lender_upload') returns uuid`. ALSO executable by `service_role` (then `p_source` must be 'lms' or 'mock'; a person must pass 'lender_upload': 22023 `source_invalid`). The API stores the bytes first (after the upload-safety check in `services/api/src/http/upload-safety.ts`) and passes the key and hash. Hints: 22023 `kind_invalid`, `mime_not_allowed` (only `application/pdf`), `storage_key_invalid`, `sha256_invalid`, `size_invalid`, `reference_invalid`, `issued_at_invalid`, `period_invalid` (statement), `period_not_allowed`, `supersedes_invalid`; 23505 `lender_reference_reused` (same reference, different hash; same hash returns the existing id), `storage_key_in_use`, `already_superseded`; 55000 `request_not_open`, `request_kind_mismatch` (a foreclosure_quote request is fulfilled only by a quote), `period_does_not_cover_request`. With `p_request` the request is fulfilled in the same transaction; a `noc` or `closure_letter` also sets the loan's closure record (first one only). Audit `servicing.loan_document.registered` (ids only: no key, hash or reference).
- `servicing.record_foreclosure_quote(p_loan uuid, p_lender_quote_ref text, p_as_of timestamptz, p_valid_until timestamptz, p_principal text, p_interest text, p_charges text, p_prepayment_charge text, p_total text, p_source text default 'lender_portal', p_request uuid default null, p_letter_document uuid default null) returns uuid`. Also `service_role` (source 'lms' or 'mock'). Money is decimal rupee text parsed by `private.parse_money_minor` (22023 `money_invalid`); stored in paise exactly as reported. 22023 `validity_order`, `as_of_invalid`, `reference_invalid`, `letter_invalid`, `source_invalid`; 23505 `quote_ref_reused` (same reference with different figures; identical figures return the id); 55000 `request_not_open`, `request_kind_mismatch`, `quote_already_expired`. Audit `servicing.foreclosure_quote.recorded` with `total_mismatch` and no amount. An expired quote may be recorded as history (not when fulfilling a request).
- `servicing.open_security_release_tasks(p_loan uuid, p_collateral_types text[]) returns integer` (tasks created). Also `service_role`. 1 to 5 distinct known types (22023 `collateral_types_invalid`); the loan must have a closure record (55000 `loan_not_closed`). Idempotent per (loan, type). `due_by` = closure `closed_at` + the security-release rule's days.
- `servicing.confirm_security_release(p_task uuid, p_confirmation_ref text) returns text` ('confirmed_by_lender'). Lender user ONLY (the system role gets 42501). Reference `^[A-Za-z0-9._/-]{3,100}$` (22023 `confirmation_ref_invalid`); 55000 `already_confirmed`.
- `servicing.set_security_release_delay_reason(p_task uuid, p_reason text) returns text` ('recorded'; 22023 `reason_invalid`; 55000 `already_confirmed`).
- `servicing.lender_loan_documents(p_loan uuid)` (same columns as `my_loan_documents`; `loan.read`; P0002 otherwise) and `servicing.lender_open_loan_document(p_doc uuid, p_purpose text default 'view') returns jsonb` (same shape as the borrower open; needs `loan.read` through a MEMBERSHIP of that lender, so a platform auditor cannot open lender-issued content; writes the access row).

Both (`authenticated` and `service_role`): `servicing.latest_valid_quote(p_loan uuid) returns setof servicing.foreclosure_quotes` — ZERO OR ONE row: the newest (`as_of`, then `reported_at`) quote with `valid_until > clock_timestamp()`. Zero rows also when the switch is off, the loan is unknown, the caller is neither the owning borrower nor a `loan.read` reader of the lender (or the system), or the only candidates are mock-source rows while mocks are not allowed. **Consumer rules for the payments stream:** a foreclosure payment must equal `total_minor` of this row, and must be REFUSED when `total_mismatch` is true (the flag travels with the row; a newer flagged quote replaces an older clean one on purpose, the lender has to re-quote).

System only (`service_role`): `servicing.expire_document_requests(p_cutoff timestamptz) returns integer` — expires still-open requests older than a cutoff the caller supplies (22023 `cutoff_invalid` if null or in the future); skips lenders whose switch is off. No age is hard-coded.

Helpers without grants: `private.servicing_text_safe`, `servicing_ist_today`, `servicing_docs_audit`, `servicing_docs_actor`, `servicing_docs_borrower_loan`, `servicing_loan_category`, `servicing_rule_days`, and the trigger functions.

## 4. Closure trigger

`servicing.loan_accounts` triggers `loan_accounts_open_closure_on_insert` (status closed or foreclosed on insert) and `..._on_update` (`status` changed to closed or foreclosed). `private.servicing_open_closure()` opens exactly one `closure_records` row per loan (`on conflict (loan_account_id) do nothing`), sets `noc_due_by` from the NOC rule when it resolves, enqueues ONE outbox event `servicing.loan_closed` through `ops.enqueue_event` with payload `{closure_id, loan_account_id, lender_org_id}` (ids only) and dedupe key `servicing.loan_closed:<loan id>`, and audits `servicing.closure.opened`. Later status changes (foreclosed, a reversal to active and a second close) neither add a record nor an event. A write-off is not a closure. Consumers (reminders stop, mandate cancellation and its verification) are not built here; the record is NOT reverted if the lender later reports the loan active again (my_closure returns the live `loan_status` next to it).

## 5. Gotchas for downstream streams

- Borrower screens call only the `my_*`, `request_document`, `open_loan_document` functions; there is no borrower RLS policy on these tables.
- A lender portal listing reads the tables directly under RLS (list the columns of `loan_documents` explicitly; `storage_key` is never selectable) and opens content with `lender_open_loan_document`.
- The test fixtures cannot create a `loan_against_securities` loan request (the platform refuses a category in feasibility review), so the lien prompt is exercised with a personal-category loan and a lender-reported `mutual_fund_lien` collateral type passed to `open_security_release_tasks`. No LAMF product is enabled.
- Approving the three rules uses `documents.applicability_rules` rows with `proposed_by <> approved_by`; the existing `protect_rule` trigger freezes an approved row.
- Tests that create mock-source rows must set `udofin.allow_mock_providers = on` for the transaction (`set_config(..., true)`).

## 6. Not done here (deferred, needs another owner or an owner decision)

- Advisory flag for a pre-payment charge on a floating-rate, individual, non-business loan (RBC 33 to 34, interpretation): NOT built. The KFS data (`documents.kfs_inputs`, `kfs_data_v1`) carries `interest.type` (`fixed`/`floating`/`hybrid`) but nothing about the borrower being an individual or the purpose being non-business (`loanType` is free text), so the condition cannot be read from existing data. It needs an owner decision on where the "individual, non-business" fact comes from (a product-category attribute or a KFS field), then a column on `foreclosure_quotes` set at insert.
- Cooling-off exit using the same quote type (spec 12.2, CF para 11): not built (no purpose column on quotes yet).
- Prerequisites for the `statements_noc` switch in `private.feature_prerequisites_unmet`: not extended (it must copy the body of migration 20261018000910 and append; two streams editing it at once would clash). Proposed reason identifiers: `document_store_unavailable` unless the lender uses manual issuance, and `mock_document_source_only`. Production reads of document bytes stay blocked by the API/adapter until the production document store exists.
- Controls matrix rows (`docs/regulatory/controls-matrix.md`) for statements, quotes, NOC, closure and security release, with the labels above; the spec 21 test list items "hash verified on read, tampered file fails, no-store header" belong to the API tests.
- API routes, contracts and OpenAPI for these functions (API stream); portal and mobile screens and en/hi text for the prompt keys.
- Owner decisions: confirm or replace the 30-day NOC platform default and the proposed 7-day statement default before approving the rules; who holds `servicing.document.issue` besides the `servicing_operator` role; whether a platform auditor (`loan.read`, platform-grantable) should see document metadata rows of every lender (today it does, exactly like loan rows; it cannot open content); whether the closure record should be reverted or flagged when the lender later reports the loan active again.

## Review fixes after the independent review of this wave (15 October 2026)

- **The system role cannot mint lender-issued records (F4).** `register_loan_document`, `record_foreclosure_quote` and `open_security_release_tasks` accept the system role only when the lender has an ACTIVE machine feed that declares the capability (`private.servicing_machine_feed_ok`: `statement`, `foreclosure_quote` or `closure_documents` on an active `lms_connections` row of kind `mock`, or `finbyx` / `generic_rest` once a connector is verified). Otherwise they raise 55000 `feed_not_active`. A real feed cannot exist in Phase 08a (those kinds can only be `blocked_unverified`), so in practice only a mock feed, and only where the mock guard allows it, can create such a record; people (lender users) and lender files are the only real sources.
- **A NOC registered before the closure was reported (F5).** The closure trigger links the newest NOC or closure letter (not superseded) already registered for the loan when it opens the closure record, so the borrower sees it as issued; `register_loan_document` still links ones registered afterwards.
